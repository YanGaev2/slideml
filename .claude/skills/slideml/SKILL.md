# SlideML: как сделать сильную презентацию

SlideML — XML-формат слайдов. Компилятор превращает его в нативный `.pptx`: фигуры, текст, графики, таблицы, фото и анимации остаются редактируемыми объектами PowerPoint.

Хорошая презентация отвечает на вопросы зрителя, а не пересказывает данные по одному факту на слайд. Поэтому работа идёт в таком порядке: план → концепция → фото → сборка → техническая проверка → минимум два дизайн-прохода. Не пропускайте шаги.

## Файлы скилла

| Файл | Что внутри | Когда читать |
|---|---|---|
| `plan-template.md` | шаблон плана | шаг 1 |
| `story.md` | сюжеты, вопросы аудитории, правила для чисел и текста | шаг 1 |
| `style.md` | арт-дирекция, 3 пресета палитры и шрифтов | шаг 2 |
| `imagery.md` | где взять фото, лицензии, оформление | шаг 3 |
| `archetypes.md` | 10 типов слайдов (раскладка) с проверенными фрагментами XML | шаг 4 |
| `visuals.md` | 7 приёмов «как показать число картинкой» с фрагментами | шаги 1 и 4 |
| `charts.md` | какой график для какого сообщения | при каждом `<chart>` |
| `rubric.md` | шкала качества и формат `review.json` | шаги 6–7 |
| `starter.xml` | тема, стили, шаблоны оформления, без слайдов | шаг 4 |
| `format.md` | справка по формату: все элементы и атрибуты | шаги 0 и 4 |
| `scripts/` | `check.py` (проверка), `fetch_image.py` (фото) | шаги 3 и 5 |

`<скилл>` в командах ниже — папка этого скилла, в которой лежит этот `SKILL.md`.

## Порядок работы

### Шаг 0. Подготовка
1. Прочитайте этот файл и `format.md`.
2. Если нет файла `<скилл>/bin/slideml.exe`, остановитесь и попросите пользователя установить SlideML: https://github.com/YanGaev2/slideml#install
3. Создайте папку `<имя>/` в текущей рабочей папке и в ней папку `assets/`. Дальше `<имя>/` — папка презентации.

### Шаг 1. План
1. Прочитайте `story.md`.
2. Скопируйте `plan-template.md` в `<имя>/plan.md`.
3. Заполните все разделы: аудитория, вопросы аудитории (минимум 5), таблица чисел с формулами, раскадровка.
4. Прочитайте `visuals.md`. В раскадровке для каждого слайда с числами выберите приём (V1–V7) или график.
5. Если в таблице вопросов больше двух ответов «нет данных», остановитесь и задайте пользователю эти вопросы одним сообщением. Если ответа получить нельзя, продолжайте с пометками `[уточнить]`.
6. Не пишите `deck.xml`, пока план не заполнен.

### Шаг 2. Концепция и стиль
1. Запишите в план две концепции и выберите одну по правилу «что зритель вспомнит завтра».
2. Прочитайте `style.md`. Запишите настроение, палитру, шрифты и фирменный приём.

### Шаг 3. Изображения
1. Прочитайте `imagery.md`.
2. Если тема физическая (место, товар, еда, люди), скачайте 2–4 фото командой `fetch_image.py` в `assets/`.
3. Запишите в план, какое фото на каком слайде.

### Шаг 4. Сборка
1. Скопируйте `starter.xml` в `<имя>/deck.xml`. Поставьте палитру из плана.
2. Для каждого слайда возьмите фрагмент архетипа из `archetypes.md` и приёма из `visuals.md` по раскадровке. Замените тексты и числа на свои, размеры считайте по формулам приёма.
3. Перед каждым `<slide>` напишите комментарий архетипа и приёма: `<!-- A7 · V1 · заголовок слайда -->`.
4. Если на слайде график, прочитайте `charts.md`.

### Шаг 5. Техническая проверка
Выполните:

```
python <скилл>/scripts/check.py <имя>/deck.xml
```

1. Исправьте каждую строку `error`, `warning` и `lint`. Подсказка исправления есть в самой строке.
2. Прочитайте раздел `DESIGN REPORT`: он описывает каждый слайд текстом (главный элемент, пустые полосы).
3. Повторяйте, пока не исчезнут все ошибки.

Результат `RESULT: DRAFT` значит: файл технически корректен, но дизайн-работа не сделана. Это не конец работы.

### Шаг 6. Ревью
1. Прочитайте `rubric.md`.
2. Если ваша среда умеет запускать отдельного агента (например, инструмент task), отдайте ему ревью: дайте только картинки и `rubric.md`, без плана. Ваша собственная оценка обычно завышена.
3. Посмотрите каждую картинку `<имя>/out/<имя>/slideN.png` и `slideN.overlay.png`. Если вы не видите картинки, используйте раздел `DESIGN REPORT`.
4. Оцените презентацию по 10 критериям. Запишите проход в `<имя>/review.json`.

### Шаг 7. Дизайн-проходы
1. Исправьте слабые места из ревью: минимум одна правка на каждом слайде с баллом ниже 2.
2. Запустите `check.py`.
3. Сделайте новое ревью и добавьте проход в `review.json`.
4. Повторяйте, пока `check.py` не напечатает `RESULT: PASS`. Для этого нужно минимум 2 прохода, последний — не меньше 16 из 20 и без нулей.

### Шаг 8. Итог для пользователя
Сообщите:
- путь к `.pptx` (`<имя>/out/<имя>.pptx`);
- одну строку на каждый слайд;
- итоговый балл из `review.json`;
- пробелы в данных (`[уточнить]`) — что пользователю нужно дать;
- источники и лицензии фото (из `assets/SOURCES.md`).

## Жёсткие правила

**История и числа**
- Главный вывод — на слайде 1 или 2.
- Заголовок — предложение-вывод с глаголом и числом, до 12 слов. Не тема («Ввод»), а вывод («Ввод вырос на 68 % к апрелю»).
- У каждого числа есть база сравнения: «+68 % июнь к апрелю». Месячный рост не выдавайте за рост периода.
- Производные числа (итог, изменение в %, значение на единицу) считайте в плане и показывайте крупно.
- Не придумывайте числа и цели. Если данных нет, пишите `[уточнить]` и сообщите пользователю. Не больше 3 пометок `[уточнить]` на презентацию: если пометок больше, уберите элемент, а не оставляйте пустую рамку.
- Называйте метрику точно: выручка — не «заработали». Не пишите причину роста, которую данные не доказывают.
- Последний слайд — решение или просьба с числом и сроком.

**Вёрстка**
- На каждом слайде один главный элемент: график, приём из `visuals.md`, фото или схема.
- Число, которое несёт слайд, покажите приёмом из `visuals.md`, а не только цифрой. «7 %» — это сетка из 100 клеток, «38 ₽ против 160 ₽» — две полосы, «3,2 млн = 26 тыс. × 122 ₽» — формула. `check.py` выдаёт ошибку, если на слайде с числами только текст.
- Пустое место обрамляет главный элемент. Если контента мало, увеличьте главный элемент, а не оставляйте пустую полосу.
- В деке из 5 слайдов — минимум 4 разных архетипа, соседние разные, есть тёмный слайд или фото.
- Текст от 14 pt, подписи от 10 pt, не больше 40 слов на слайд.
- Для подписей и абзацев ставьте `h="auto"`.

**Образ**
- Иконка только поясняет текст рядом и не больше 48 pt. Иконка не может быть главным элементом слайда.
- Не ставьте пустые цветные плашки «для красоты». Цветом выделяйте данные.
- Если тема физическая, на обложке фото.

**Анимация**
- 1–2 анимации на слайд и только там, где они показывают изменение. По умолчанию анимаций нет.
- Morph: один `id` у элемента на соседних слайдах и `transition="morph"`. У такого элемента нет `<anim>`.

**Чего не делать**
- Не показывайте служебные `id`, координаты и рамки выделения на слайдах.
- Не копируйте координаты из чужих презентаций. Берите фрагменты из `archetypes.md`.
- Не меняйте файлы скилла.
